## 导入方法

1. 复核原仓库和目标目录的当前状态，保留本目录全部文档及用户新增文件。
2. 将选定提交导出到临时目录，检查文件清单后将应用、包、脚本、依赖锁文件、地图及运行时归档导入目标工作区。不要直接覆盖整个目标目录。
3. 根 README 和 AGENTS 采用本项目版本；来源 README、根 AGENTS 和旧施工说明存入 `docs/upstream/` 作为参考。基线中有作用域的 AGENTS 保留并逐项合并用户最新测试安排。
4. 基线的根 LICENSE、第三方声明及素材许可按原内容保留。导出时不把源仓库 `.git`、未跟踪文件、个人配置、node_modules、用户数据和开发状态一起复制。
5. Git 归档不包含子模块内容。需要上游源码时，依据原 `.gitmodules` 获取固定提交；不要把空子模块目录当作依赖已准备完毕。
6. 使用基线声明的 Node、Corepack 和 Yarn 版本及锁文件准备依赖；先解决本地构建入口，再接入新模块，不顺手升级全部依赖。
7. 记录实际导入提交、目录映射和有来源依据的移植项到开发进度。初始化版本控制可在开始实施时处理；创建分支、提交、推送仍遵循用户授权范围。

导入时采用可恢复、逐项复制的方式，禁止清空目标目录来消除文件冲突。发现现有文件与基线同名时读取并合并，不能假设它们可丢弃。

## 桌面路线

本次采用本地服务启动器加浏览器界面的已有路线，不迁移到实验性的另一套官方桌面运行时。交付目标为 macOS Apple Silicon。公开快照的旧说明主要覆盖 Windows 和 Intel Mac，因此 arm64 的打包、运行时选择及启动适配是需要完成的工作，不能假设基线已经支持。

后续提交里的 arm64 实现只在确认来源可复用后移植，否则在本项目启动器层独立实现。无需更换整个上游运行时来解决发行目标。

发行说明记录实际签名、公证状态及首次启动方式；使用具备的证书能力打包，不在未实际验证时承诺所有机器无提示启动。凭据只在发行环境配置，不写入源码或文档。
