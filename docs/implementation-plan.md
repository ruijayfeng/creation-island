## 后续改造范围

| 范围 | 保留的基础 | 需要达到的新状态 |
| --- | --- | --- |
| 品牌与角色 | 现有地图布局、交互点与可复用动作 | 阿启、拾页、阿渡及海岛工坊的外观、道具、标牌和对白；保留素材来源记录 |
| 主交互 | 三维世界、角色和岛内消息桥 | 默认由岛上角色与对象承接项目工作；普通流程不要求进入独立工作台 |
| 项目与对话 | 原 Workspace、Session、原生输入与执行引擎 | 新建和打开真实项目，关闭、重启及切换后恢复同一工作 |
| 执行与权限 | 固定运行时的真实工具、审批与日志 | 明确展示操作和权限；任务、审批、失败与世界状态一致 |
| 结果与预览 | 原对话和运行能力 | 项目归属、预览进程、实际访问状态、修复入口与大屏体验 |
| 文件和历史 | 原项目文件与历史入口 | 真实本轮改动、明确的成果节点、恢复副本，不覆盖已有仓库 |
| 岛上成果 | 已有六个展示位置 | 当前项目精选成果、真实封面及版本、点击查看与继续 |
| 交付 | 桌面启动器与打包经验 | 按项目类型导出实际可交付文件，说明条件和排除项 |
| 兼容 | 三类作品存储与既有导出 | 保留旧版互动作品访问，不静默删数据或改协议 |

本轮按真实项目与岛内创作 → 执行与权限 → 预览、成果、交付 → 角色场景 → 集中验收修复 → 桌面交付推进。已实现与已验收状态记录于 progress.md。

## 开发前需要确认的能力

优先核对权限、预览生命周期、成果文件快照与恢复、交付排除规则，以及原生会话恢复。产品要求和未确认条件见 direction-reset.md。不能通过添加一个成功提示绕过尚未具备的底层能力。

复用固定上游接口，不因为改方向重写 Agent 执行引擎。地图只投影状态，不持有独立文件执行、会话和审批系统。

## 验证原则

后续仍按用户要求先完成整体开发，再集中测试和修复。过程只做必要的编译与连接检查。集中验收围绕开放项目的完整任务、小岛交互、权限与恢复、真实预览及项目交付组织，不机械复用三类结构化作品的成功率。

现有 20 项作品测试、18 组模型场景、界面和发行包检查仍作为旧版历史记录。它们不能证明开放式 AI 项目创作已经通过验收。
