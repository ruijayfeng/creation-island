# 创作岛产品终态

2026 年 10 月 8 日方向纠正版。用户已明确选择回到开放式 AI 项目创作。本文件定义终态目标；0.2.0 正在执行开发与集中验收，实际完成状态见 progress.md。0.1.0 属于历史三类作品版本。具体画面见 [产品体验说明](product-experience.md)，历史规格保存在 archive/structured-creation-v1/。

## 产品定位

创作岛是一个以可探索小岛为主界面的 AI 项目创作环境。用户在岛上与制作伙伴阿启合作，把自己的想法做成真实项目，体验结果、继续修改，并保留源码和工作记录。

主要服务有具体创作想法、愿意体验和判断结果，但希望少处理开发工具配置和繁杂操作的个人创作者、学生和项目初学者，也允许有经验的用户打开已有项目。降低启动门槛与保持对作品的控制，是设计目标，尚未获得用户研究或商业收入验证。

用户来这里是为了做出能用、能演示、能继续修改的项目。小岛承担功能导航、任务状态、工作连续性和成果呈现。探索和角色互动提供情绪体验，不作为创作权限的解锁条件。

核心对象是项目。一项项目工作包含需求、会话、文件修改、运行结果和后续迭代。问答、贺卡、故事可以保留为示例，不再规定产品允许的内容和交互。

## 开放创作的范围

用户可以直接提出“做一个读书记录工具”“给社团做一个活动页面”“做一段能操作的像素冒险”“调整我已有网站的首页”等需求。阿启读取当前项目，使用真实工具创建和修改代码、整理资源、运行命令、检查结果并继续修正。用户可以给出文字和参考文件，查看执行过程，在需要时处理授权。

首版重点验收本地可运行的网页、交互原型、小工具和轻量 Web 游戏。结果允许多页面、多种交互和不同项目结构，不限制为固定内容模板。依赖和框架必须符合本机运行条件。

对其他技术栈或复杂需求，允许继续讨论、查看代码和明确实施条件；没有相应环境时，不显示为可以一键运行。原生移动端发行、复杂服务部署、多人实时系统不作为本次端到端承诺。需要账号、云服务、付费接口或额外环境的能力，在执行相关步骤前说明。

首版仍是 macOS Apple Silicon 本地应用，复用现有启动器与固定 Agent 运行时。用户自配模型；可以先探索和试玩内置示例，需要模型时再配置，保留已经输入的想法。不承诺所有依赖均已内置或任意项目都能离线运行。

## 小岛与项目

一个项目对应一份小岛工作档案。当前小岛始终明确属于哪个项目，角色状态、对话、文件、预览与成果都属于该项目。切换项目恢复其工作档案；首版复用同一套地图，不为每个项目生成新地图。

没有项目时，小岛是欢迎空间，灵感夹提供标明“内置示例”的演示。用户向阿启提出想法后，通过项目名称和简短说明创建项目。默认在应用管理的位置建立独立文件夹，提供打开位置入口；也允许用户明确选择其他位置或已有文件夹。

打开已有文件夹显示名称、位置与接下来允许的操作。只打开和浏览不触发模型调用、依赖安装或启动命令。原文件、Git 历史和未提交内容保留，不能把“打开项目”解释为允许清理或重置目录。

角色命名、外观、对白与地点表达采用 [品牌与角色设计](brand-and-characters.md) 的当前推荐稿。

## 岛上的主要位置

| 位置 | 用户意图 | 最终交互 |
| --- | --- | --- |
| 造物台 · 阿启 | 做点东西或继续修改 | 点击阿启或走近互动，在岛内打开当前项目对话，提出需求、附参考资料、看进度、处理审批、查看结果 |
| 留页屋 · 拾页 | 找回上次工作 | 岛内项目簿：新建、选择项目、检索会话、继续上次任务；不额外建立独立 AI 会话 |
| 出发码头 · 阿渡 | 看实际做了什么，把成果拿走 | 岛内文件面板：目录、支持的内容预览、本轮改动、交付清单、项目导出 |
| 作品沿岸 | 体验已经确认的成果 | 六个固定位置显示当前项目精选成果版本，点击查看说明、试玩可运行版本或继续迭代 |

灵感夹是直接点击的速写夹，提供示例与建议起点，不是强制先选类型的页面。设置、通知和帮助使用轻量固定入口。其他居民和景观可承担本地对白与探索，不虚构后台多 Agent 分工。

不要求按顺序拜访每个角色。阿启的结果中也能直接打开文件、历史与交付操作，与角色入口打开同一内容。

## 最终界面

### 小岛总览

启动后看到实际三维小岛、角色、中央创作台与自己的展品。固定界面只保留项目名称、必要任务状态、通知和设置，首次使用有可关闭的简短引导。

大块欢迎标语、三列最近作品卡和整页导航不再覆盖地图。最近项目由“继续上次项目”短入口和拾页项目簿承接，地图上的对象保持可辨认、可点击。

常用功能提供点击对象、走近互动和固定快捷入口三种等价路径。快捷入口打开同一个岛内交互；无需等人物走路、搬运或剧情结束才能操作。

### 与阿启对话

点击阿启，视角温和聚焦创作台，右侧展开对话面板，阿启与部分环境仍可见。面板标出项目和会话，包含输入、附件、模型与权限信息、任务状态及停止入口。

默认突出本轮目标、必要追问、待授权操作和结果。长工具日志可展开，不隐藏失败、不显示伪进度。复杂对话、代码和预览可以由用户主动展开专注模式。

收起面板回到刚才的位置，保留项目、会话、未发送输入和运行中任务。关闭不是取消，停止有独立按钮。重新点击阿启恢复同一工作，不新建空对话。

### 体验和修改作品

运行结果可访问时，阿启提供“看看作品”。在创作台上下文中展开真实项目预览，允许放大。模型文字中出现网址不等于预览就绪。

用户在预览旁提出修改要求，可附截图、页面或文件。支持“只改首页标题区”等局部需求，但任意项目的语义范围需要理解并通过实际文件改动核对，不能继续承诺原三类模板的确定性范围保证。

“点任意元素就能无误定位源码并修改”不作为默认能力。可靠的描述、截图和文件上下文先做通；结构化内容编辑器不再是通用项目的必经入口。

### 文件和改动

阿渡面板展示本项目文件与本轮修改摘要。用户能查看源码及支持的图片/文本内容，辨认新增、修改、删除的文件，展开差异。不能只显示模型自述的“已完成”。

执行过程中，文件可能已经改变。界面不声称所有代码都在“点击采用”后才写入。本轮结束后，可以继续修正、保存成果节点，或从历史快照建立恢复副本。

### 成果展示

展示区呈现用户确认的成果节点，不是每轮模型回复。展品带名称、真实截图或合适的文件图示、版本与状态。没有截图时使用明确类型的封面，不生成虚构成功页面充当成果截图。

用户选择“保存成果”后，形成文件快照与说明，再决定是否放到展示位。首次可建议空位，不静默替换已有展品。六个位置用于精选展示，不限制项目或成果总数。

只有保存成果成功时触发短暂、可跳过的演出。任务结束、失败、审批拒绝或仅得到文字回复都不触发“作品完成”。旧版长时间自动搬运与强制剧情不进入主流程。

## 一次完整使用

1. 用户在岛上点击阿启，说“做一个有筛选和收藏的读书记录工具，风格安静一点”。
2.阿启明确关键条件，例如数据是否仅保存在本机。合理默认直接写入简短方案；用户确认后创建项目并开始，已有项目先读取上下文。
3.阿启修改真实文件，按权限执行依赖安装、运行与检查。待授权操作在对话和岛上通知中说明；拒绝后保留项目，给出替代路径或限制。
4. 用户收起面板探索。阿启显示真实工作状态，普通结束以非阻断提醒告知，待授权保留持续入口。
5. 用户打开预览，实际添加书目、筛选、收藏。阿启同时提供本轮改动、实际检查结果和未完成部分。
6. 用户要求“把收藏按钮移到卡片右上角，其他功能保留”。阿启继续修改，重新准备预览；阿渡展示本轮文件差异。
7. 用户确认这版达到要求，保存成果、命名并放到展台。任务结束与用户确认分别记录。
8. 导出源码包和说明；支持静态构建的项目另提供静态发布包。需要服务的项目明确运行条件。
9. 下次启动恢复项目、会话和展品。未发送输入保留；中断任务不自动重跑，停止的预览服务在用户请求后重新启动。

整个普通流程不要求打开独立高级工作台。高级工作台仅供深入诊断和熟悉专业界面的用户，进入前后仍为同一项目与会话。

## 状态和用户控制

| 事实状态 | 岛上表现 | 用户操作 |
| --- | --- | --- |
| 空闲或待输入 |阿启待机，有草稿时可继续 | 发送需求、切项目、查看成果 |
| 正在执行 | 工作动画及简短状态，无虚构百分比 | 看过程、停止、收起面板；补充信息按运行时真实能力排队 |
| 等待授权或补充 |阿启和通知有持续标记，文字说明原因 | 允许、拒绝、回答或停止；收起不自动回答 |
| 本轮结束 | 输出摘要与下一步，不等同于可用作品 | 看改动、启动或打开预览、继续修改 |
| 预览可用 | 标记当前项目、当前内容或历史版本 | 实际体验；服务可访问不等于功能全部正确 |
| 失败或中断 | 保留原因、已有改动和最后可用成果 | 看日志、继续修复、明确重试或创建恢复副本 |
| 已保存成果 | 展品引用保存版本 | 查看、交付、继续迭代 |

首版默认全局一轮文件写入任务，额外请求明确排队；同一项目不能有并发写入任务。若底层无法提供可靠队列，明确提示等待当前任务结束再开始，不伪造已受理状态。切换项目只切换视图，不取消、不重发、不错接任务。通知点击回到来源项目与会话。多 Agent 并行创作不在首版承诺中。

角色提示词不构成文件隔离或权限沙箱，不以默认完全权限掩盖交互。默认权限、项目外访问及高影响命令需在后续技术核对中确认，界面真实显示采用的模式和待审批动作。

## 预览 保存和交付

区分项目当前文件、本轮任务记录、用户保存的成果节点。当前文件在执行中变化；会话描述过程；成果节点引用明确的文件快照与说明。

新项目提供保存成果和恢复入口。已有项目的 Git 历史与未提交内容保留；恢复默认创建独立副本，用户决定是否替换当前工作，不能后台重置仓库。保存失败时不出现成功展品。

历史展品不能指向最新运行中的页面。先显示该版本截图与说明；需要运行时，用对应快照准备预览，并显示环境是否就绪。无法重建就提供源码及原因，不能以当前版本冒充历史版本。

| 项目情况 | 可交付内容 | 对用户的说明 |
| --- | --- | --- |
| 通用项目 | 源码、资源、运行说明组成的项目包 | 展示文件清单，排除凭据、运行日志、依赖缓存及不应公开的个人文件 |
| 构建成功的静态 Web 项目 | 静态发布目录及说明 | 用于静态托管，不保证双击某个文件即可运行 |
| 实际验证的单文件作品 | 独立 HTML | 确实自包含且不依赖服务时，才提供离线打开说明 |
| 依赖服务的应用 | 源码包、配置示例、启动说明 | 明确所需环境、账号或服务，不声称无需配置 |

导出前显示版本、包含内容和排除说明，取消没有副作用。生成的运行说明需与实际结构、启动方式核对。本次不包含默认公网部署、整岛在线分享、云端同步、访客账号或付费系统。岛上展示不冒充已经发布到互联网。

## 小岛的实际作用

小岛用角色和地点组织操作，把后台工作与等待放在持续可见的空间，让用户关闭对话后仍能找到工作，并把确认过的成果保留为可再次进入的对象。

这些是设计理由，不是已验证的效率优势。后续观察新用户能否找到创作、预览和历史入口，是否理解后台执行，再次打开是否能继续。如果小岛只增加寻路和点击，或普通任务仍必须进入独立工作台，纠正就没有完成。

## 视觉和体验边界

总览以三维世界为主，角色和位置有易辨认的轮廓与标签。岛内对话、结果和文件使用统一暖白表面及清晰文字。关键状态同时使用文字和图形，不只依赖颜色、音效或动画。

面板有明确展开、收起和返回关系。视角可聚焦，可关闭动态，不自动拖走正在操作其他内容的用户。专注模式由用户主动打开；窄窗口可覆盖全屏，返回仍恢复原岛屿上下文。轻量模式提供相同项目与角色入口，世界失败不阻断工作。

不新增体力、签到、生产资源、随机奖励或强制成长任务。装饰编辑、无限扩张地图、角色社交不在本次范围。

## 最终完成判据

1. 从岛上提出自己的需求，创建真实项目并体验结果，无需先选固定作品类型。
2. 已有项目能继续修改，文件和历史归属清晰，原内容不丢失。
3. 普通创作、必要授权、预览、修改、保存成果和交付全程在岛内完成。
4. 阿启、通知、会话和文件显示同一事实；关闭不取消、返回不重发、切项目不串记录。
5. 集中走通内容站点、交互工具、轻量游戏、已有项目修改四类任务，记录失败及限制，不宣称任意需求必定成功。
6. 展品引用真实成果，区分任务结束与用户确认，历史不冒充当前版本。
7. 不操控人物走路也能完成流程，主动探索仍可用；专注模式能原路返回。
8. 真实三维世界和真实项目能力共同构成交互，静态背景或无关角色动画不算完成。

具体实现与验收状态以 progress.md 和开放项目验收记录为准；产品目标不等于通过验收。
