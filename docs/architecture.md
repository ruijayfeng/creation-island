# 技术结构与实现约定

本文件定义待实现的技术方案，功能边界以 [产品规格](product-spec.md)为准。下列旧路径是来源定位，不代表代码已经导入本目录；新路径在基线导入时映射。

## 一 核心实现方式

### 作品数据是唯一内容来源

模型输出结构化数据，应用自己的播放器负责把数据呈现为可玩的作品。编辑器预览、收藏试玩和导出使用同一版本的渲染器，防止界面中正常、导出后失效。

推荐的数据流为：

```text
用户想法或修改请求
  → 明确作品类型与创作卡
  → 读取当前草稿和允许修改范围
  → 调用模型生成内容或变更提案
  → 校验结构、业务规则和变更范围
  → 使用固定播放器生成候选预览
  → 用户采用，更新草稿
  → 用户保存，形成不可变版本
  → 收藏展示、继续编辑或导出
```

本次不把自由生成 HTML 作为正式主流程。它自由度高，但与受控内容编辑、局部修改和稳定恢复的实现方式不同。先将三种作品的内容与交互做完整；任意代码创作另行定义产品边界。

### 直接复用现有模型能力

当前 `src/model-test.ts` 已经通过 `ctx.llm.stream`、`agentDefaultModel.currentSelection()` 和 `tools: []` 调用模型；公开 MIT 快照对应文件也包含这条路径。可以在新产品宿主中封装为生成服务，集成时核对固定依赖版本的流式事件类型。

正式创作请求使用空工具列表，不授予终端、任意文件读写或目录遍历能力。宿主只通过作品存储服务写应用自己的数据。原 Harness 工作台放在开发者入口，其会话和权限不参与默认作品流程。

模型侧不强依赖某个服务商的结构化输出特性。用明确输出约定加本地解析校验实现；支持原生约束的服务商可由适配层启用，返回结果仍经过相同校验。

### 自然语言修改

采用有类型的修改操作，例如修改一道题、替换一段祝福、修改节点文本、连接两个故事节点或切换主题。模型提交对象 ID、操作类型、变更内容和简短说明，宿主校验后应用。

不要直接执行任意 JSON 路径或任意代码。对象使用稳定 ID，题目排序变化后，“第三题”在提交前解析成当时那道题的 ID；请求携带当前草稿修订号。

“只改第三题”应只允许该对象变化；“整体换个主题”可以允许更大范围，但仍展示变更摘要。修改幅度无法确定时先询问，不能把整份重做当作局部调整。

## 二 数据与状态设计

| 对象 | 保存什么 | 关键约束 |
| --- | --- | --- |
| Work 作品 | ID、类型、标题、创建时间、草稿、当前版本、回收站状态 | 用户操作围绕作品，而非源代码目录 |
| Draft 草稿 | 结构化内容、schemaVersion、rendererVersion、revision | 自动保存，有明确修订号 |
| Version 版本 | 不可变内容快照、渲染器版本、改动摘要、时间、导出文件或校验摘要 | 恢复可重现，不能只保存聊天记录或文件哈希 |
| Job 任务 | ID、作品 ID、基准修订号、状态、模型配置标识、取消标识、结果摘要 | 不保存密钥；结果提交必须检查基准是否仍有效 |
| Proposal 候选修改 | 基准修订号、已校验的修改、候选内容、说明 | 采用或放弃；不自动覆盖草稿 |
| Showcase 展示位 | 固定槽位 ID、作品 ID、版本 ID | 只引用已保存版本 |

创作中的用户请求和伙伴回复是作品流程记录，按作品保存有限上下文；不复制 Harness 的 Session、工具历史和会话持久化。原高级工作台继续由 Harness 自己管理。

### 状态规则

任务状态为 queued、generating、validating、ready、failed、cancelled 或 interrupted。用户界面将其映射为自然语言。

每个作品同一时刻只允许一个生成任务；不同作品可保存草稿，但首版全局最多一个模型任务，其他请求明确排队。等待期间可以继续试玩旧版本。

每次提交使用唯一请求 ID 和基准 revision，重复提交返回原任务。模型结果返回时重新核对任务状态、作品是否存在及 revision；不一致则不写入草稿。用户在生成中手动编辑，会使旧候选失效，提示依据新内容重试。

取消后停止消费生成流并尽力终止调用；即使服务商稍后仍返回内容，也不得提交。关闭应用时保留已有草稿，重启把未完成任务标为中断，由用户手动重试，避免后台重复扣费。

### 持久化

作品领域采用独立 JSON 状态文件和原子替换写入，与 Harness 会话存储隔离。每次命令同步复制状态、落盘并替换，版本和当前引用在同一事务文件中提交。一次“保存版本”需要先可靠保存快照，再更新当前版本引用；写入失败保持旧版本可读。若存储 API 不支持跨记录事务，使用不可变快照、最后提交引用和启动恢复检查实现。

自动保存失败要清楚显示“尚未保存”，保留内存编辑内容并允许重试。不能仅依据用户点击就显示已保存。

新产品使用独立数据目录，默认不迁移、改名或覆盖原 QCode 的数据。导入旧内容仅通过显式操作和受支持格式处理。渲染器升级需保留旧版本播放能力或提供经过检查的数据迁移。

编辑草稿允许暂时不完整，例如用户正在新增一道题；保存草稿时记录字段错误，预览保持最近一次有效内容。“保存版本”和导出必须通过完整校验。用草稿与正式内容两级校验，避免输入过程中因为暂时缺项而丢失编辑。

## 三 预览与导出的实现

三种类型共享播放器基础，类型模块分别负责问答、贺卡和故事。播放器只依赖作品数据及内置资源，不依赖创作岛的路由、接口、模型和宿主状态。

预览放在受限 iframe 中，脚本只来自应用自己的播放器；模型内容作为文本或经过类型校验的数据传入。数据不能变成可执行 HTML。JSON 嵌入脚本时处理结束标签等转义，外链与任意脚本字段不在数据协议内。

导出时将版本快照、播放器脚本、样式和内置图形打包为一个 HTML。导出已保存版本；有未保存草稿时提供“保存后导出”或“导出上一保存版本”。文件中的标题、作者可见信息和内容由用户确认，去除请求记录、提示词、密钥、本机路径和诊断日志。

可编辑作品包保存协议版本与可编辑数据，不装入模型密钥或程序代码。导入前校验格式、大小和引用；建议首版上限 2 MiB。支持的版本直接导入，不支持的版本明确拒绝并保留原文件。

导出完成要提供打开文件和显示位置入口。验证应在不运行创作岛服务、断网的另一台电脑浏览器执行。桌面浏览器是本次交付基准；响应式布局不等于手机上的文件接收方式已得到支持。

缩略图先用类型、标题、主题颜色和内置图形生成稳定卡面，与展示位共用，不为截图额外引入浏览器服务。

以下是职责划分，不要求每个职责机械拆成一个小文件：


服务边界至少涵盖：列出与读取作品、创建和更新草稿、开始与取消生成、读取任务、采用候选、保存与恢复版本、复制与删除、导入与导出、读取与更新展示位。

所有写操作使用 requestId；涉及已有内容时校验 expectedRevision。前端不能传入任意文件路径，存储位置由宿主依据作品 ID 决定。生成等消耗额度的接口需复用已有本地来源校验，不能只因为监听本机就允许任意网页调用。

## 五 接口落地约定

接口统一放在新产品命名空间，前端和地图入口调用同一作品服务。路由名在实现时按已有传输层习惯决定，以下输入和结果约束保持一致。

| 操作组 | 输入约束 | 返回结果 |
| --- | --- | --- |
| 创建及复制 | requestId、类型或源作品 ID | 新作品及初始草稿 |
| 草稿编辑 | 作品 ID、expectedRevision、受支持内容 | 新 revision 和字段错误 |
| 开始生成 | 作品 ID、expectedRevision、请求和允许修改范围 | jobId，重复请求返回原任务 |
| 获取及取消任务 | jobId；核对关联作品 | 当前状态及候选 ID |
| 采用候选 | proposalId、expectedRevision | 更新的草稿；过期返回冲突 |
| 保存及恢复 | 作品 ID、expectedRevision、可选源版本 ID | 保存版本或恢复出的新草稿 |
| 导入导出 | 作品包或已保存版本 ID | 新作品，或导出结果及位置 |
| 展示位 | 槽位、作品及版本 ID、expectedRevision | 新展示状态 |

请求去重以持久记录为依据，重启后未完成任务标记中断；用户发起新任务才再次调用模型。错误统一分类为配置错误、额度或限流、超时、内容不合格、版本冲突、存储失败和格式不支持。界面收到可理解的信息，诊断细节去掉凭据后留在本地。

文本编辑使用短间隔合并保存，显示保存中、已保存和保存失败；关闭窗口前处理未落盘内容。模型请求设超时和输出上限，输出截断视为不合格。模型停止事件不能直接当作作品成功。

## 六 开发约束与测试区分

类型、内容引用、修订冲突和文件边界校验是运行时逻辑，随功能实现。批量执行场景测试、模型质量检查和发行包验证按照 [统一测试安排](testing-and-release.md)，集中在整体开发之后开展。

## 七 内容协议与 AI 输出

统一内容协议包含 `schemaVersion`、`kind`、`title`、`theme`、`content`。`kind` 取 quiz、card、story，`theme` 取 fresh、celebration、night。作品 ID、revision、版本 ID 和任务状态由宿主生成，模型没有修改权。

| 类型 | content 结构 | 完整版本检查 |
| --- | --- | --- |
| quiz | intro、questions、ending；每题有 id、prompt、options、answerId、explanation；选项有 id 和 text | 题数与选项数符合产品规格；ID 唯一；答案引用有效；全部必要文字非空 |
| card | recipient、sections、signature、closing；每段有 id 和 text | 段数符合规格；顺序明确；无重复 ID；必要文字非空 |
| story | intro、startNodeId、nodes；节点有 id、text、choices 或 ending；选项有 id、label、targetNodeId | 引用有效、节点可达、无循环、每条路线可结束；结局数量符合规格 |

草稿允许缺字段并附错误信息，正式版本使用严格 schema。标题上限 80 字符；单题文本 300、选项 120、解释 600；贺卡单段 1000；故事单节点 1500。限制由前后端共享定义，界面显示余量，禁止静默截断。长度以同一实现口径计数，导入遵守相同限制。

AI 输出只接受三类结构：`clarify` 包含需要用户补充的问题；`create` 包含完整作品内容；`modify` 包含受支持操作和摘要。输出包中的任务标识由宿主绑定，不相信模型自报的作品 ID 或 revision。解析失败或校验不通过时，将具体错误及允许范围回传，最多一次修复。

修改操作包括 setTitle、setTheme、replaceQuestion、insertQuestion、removeQuestion、reorderQuestions、replaceCardSection、insertCardSection、removeCardSection、reorderCardSections、updateCardMeta、replaceStoryNode、addStoryNode、removeStoryNode、setStoryStart、updateIntro、updateEnding。每个操作只接受对应类型和明确字段；数量和引用在应用整组操作后重新检查。

操作原子应用到基准草稿的副本，任何一步不合格都不提交。候选展示根据实际前后差异生成摘要，不能只复述模型声称修改了什么。故事删除节点时必须在同一组操作中处理所有受影响引用，否则退回修正。

生成提示由作品类型、用户确认的创作卡、允许字段、内容规则和输出 schema 组成。修改提示增加当前内容、目标对象和允许操作。把用户内容作为数据传入，不让其中的文字扩展模型权限。只保留完成当前作品所需的有限上下文，避免把整个应用历史加入请求。

主题、图形和动效不由模型输出 CSS 或脚本，模型返回允许的设置值。生成文件时渲染器将文本安全编码，预览与导出保持一致。
