# 创作岛下一轮：从开始创作到持续积累

2026-10-08。状态：**主体已实现待验收**。用户已要求开始开发；本轮进行实现和必要局部连接检查，尚未执行集中验收。基于 0.2.0 本机已验收候选版，建议作为 0.3.0 的功能范围；版本号不表示已经发布。实际状态以 [开发进度](progress.md) 为准，任务拆分见 [开发准备清单](next-iteration-tasks.md)。

## 当前实施说明

实现沿用下方方案，实际证据以 progress.md 为准。上下文通过公开 `system-prompt/assemble` 瀑布接口加入用户角色快照；运行时在 pre-step 之前组装，不能在 pre-step 才注册。按真实 Agent/Session 找项目，每轮固定笔记副本；值通过单次变量插值，不把笔记放进全局人设。

媒体独立于源码和运行时附件，回执参数仅存 SHA-256；原生模型提交保持原 requestId 与冻结载荷。截图编辑只将处理后的底图落盘；历史底图的再次编辑记录派生来源。当前模型图像能力未知时默认只传文字，真实图片链路仍待探针。

静态预览响应加入只回答随机挑战与 previewId 的来源探针，捕获前后核对当前 iframe 来源；不获得宿主文件、会话或世界权限。Node 和来源无法确认的页面不能拍版本封面。仍需要用户确认画面，不能把浏览器截图称作独立服务端证明；捕获兼容性尚待实测。

首版复制在开始前可取消；受理后完成短文件事务，不提供中途回滚。离开面板不撤销操作，迟到响应不切换用户当前项目。封面清除独立命令和自动模型图像能力识别尚未加入，本轮已有展品移出和重拍替换。

## 目标与取舍

下一轮解决四个连续的问题：不知道从什么开始；隔几天回来接不上；看得出问题但描述不清；做完之后缺少可回看、可展示的积累。

以四项功能连成一次完整体验：**试玩真实示例 → 复制并修改 → 记录目标和下一步 → 在预览中标注反馈 → 保存明确版本并陈列**。直接提出新需求、打开已有项目仍是同等入口，示例不限制创作类型。

本轮不增加新角色、资源收集、创作等级或强制剧情。阿启负责制作与修改，拾页承接项目记录，阿渡继续负责文件与交付，灵感夹承接起点，作品沿岸承接积累。保持当前地图布局和岛内面板，不增加独立必经工作台。

| 功能 | 开发前基础 | 下一轮新增价值 | 优先级 |
| --- | --- | --- | --- |
| 可试玩起点 | 开发前灵感夹为三条文字建议和兼容作品入口 | 不配模型也能先体验，再获得可修改的真实文件 | 第一批 |
| 项目记录与续作 | Workspace、Session、输入草稿、任务与成果历史 | 找到上次做到哪里、为什么这样做、接下来做什么 | 第一批 |
| 预览标注反馈 | 隔离 iframe 预览、原生会话及图片附件能力 | 用画面和编号明确修改位置，保留反馈上下文 | 第二批 |
| 真实封面与沿岸 | 不可变成果、六个展示引用、标题与通用图示 | 认得出自己的成果，辨别版本并继续迭代 | 第三批；复用截图能力 |

## 一、灵感夹：先玩，再改成自己的

### 用户流程

点击灵感夹，在岛内浏览少量真实示例。卡片显示能做什么、可尝试的操作、运行条件和“内置示例”标识。先点“试玩”，再选“复制到我的项目”。复制后进入新项目的阿启面板，可选修改建议填入草稿；不自动发送模型请求。

首批制作四个可离线运行的静态 Web 项目，全部使用真实 HTML/CSS/JavaScript 文件，无安装、登录、外部字体或在线接口依赖：

| 起点 | 必须能实际操作的内容 | 建议的第一次修改 |
| --- | --- | --- |
| 社团活动小站 | 活动列表、分类筛选、详情切换 | 换成自己的活动与视觉风格 |
| 阅读记录工具 | 添加、编辑、搜索、完成状态、浏览器本地保存 | 增加评分或自定义标签 |
| 海风接物小游戏 | 开始、键盘/触控操作、得分、结束与重开 | 修改道具、速度或胜负规则 |
| 展览导览原型 | 地点列表、作品详情、收藏与返回 | 换成自己的展览或旅行路线 |

这些是默认内容选题，不是项目类型枚举。每个示例提供中英文内容、说明、文件清单、版本和来源。浏览器保存的数据属于示例试玩环境，不承诺随项目复制或导出；工具内明确这一点。

### 功能边界

- 示例包只读，试玩使用应用管理的临时副本。重置只影响该示例试玩副本，不修改用户项目；运行时来源存储的清理与文件重置分别说明。
- “复制”创建新的 Workspace、目录和项目记录，保留 starterId、starterVersion、清单哈希作为来源。两次有意复制可获得两个项目；一次请求重试只产生一个。
- 未配置模型时，仍可试玩、复制、看文件和使用静态预览。开始 AI 修改时再引导配置，并保留输入。
- 复制进度、磁盘不足、包校验失败和取消都提供确定结果。创建中断后能完成原操作或清理应用拥有的临时目录，不留下多个空项目。
- 示例更新只影响以后复制的新项目。已有副本不自动合并或覆盖。
- 旧问答、贺卡、故事入口继续标为“兼容作品”，不与新起点混用数据协议。

首版不做模板市场、远程下载、任意仓库模板导入或模板自动升级。不能直接把含私人输入的本机验收作品作为发行示例；重新整理可公开内容，并登记代码、素材和许可证来源。

## 二、拾页：项目记录与继续提示

### 用户流程

再次进入小岛，显示一条有依据的提示，例如“阅读工具：上次修改了筛选，尚未保存新成果”。点“继续”恢复对应项目与会话；不自动执行。拾页的项目簿提供“项目记录”页，可查看和编辑目标、已确认决定及待办。

记录分两层，视觉上分开：

| 内容 | 谁决定 | 更新规则 |
| --- | --- | --- |
| 项目简介：做什么、给谁用、约束 | 用户 | 显式保存，可编辑和清除 |
| 已确认决定 | 用户确认 | AI 可以建议，不能静默替换 |
| 待办与完成状态 | 用户 | 勾选或接受建议；任务结束不自动等于待办完成 |
| 最近进展、任务中断、上次成果 | 宿主记录 | 从真实任务、文件差异和成果计算，附时间及来源入口 |
| AI 整理建议 | 阿启 | 用户点击“请阿启整理”才发起；先出建议，再由用户加入记录 |

自动提示只说能确定的事实。例如“改动 3 个文件”“任务中断”“上次保存于……”；“功能正确”“已经上线”等结论不从模型总结推断。找不到可靠记录时显示“打开上次会话”，不编造续作摘要。

### 让记录真正帮助下一轮

项目提供“让阿启参考已确认记录”开关，启用时在新一轮开始展示记录版本及可展开内容；关闭后不追加新上下文。已进入历史会话的内容不会因关闭开关而从模型历史消失，界面说明这一边界。

优先使用固定运行时公开的 `systemPrompt.context` 动态上下文接口：其声明支持用户角色的持久化上下文快照。按 Agent/Session 作用域绑定项目，传入已确认记录和来源，**不把笔记写进全局人设或权限规则**。开发前验证作用域映射、取消注册和文本插值行为；无法可靠接入时，降为用户可审阅的“带记录继续”消息，不伪称后台已经记住。

每轮冻结一次记录 revision，中途编辑从下一轮生效。模型整理使用当前阿启会话和相同执行互斥；不会因打开项目簿产生隐藏调用或额外 Agent。模型建议先以会话文本呈现，首版由用户选择并编辑后保存，不新增绕过宿主校验的模型写状态通道。

首版记录上限暂定简介 2,000 字、决定 20 条、待办 30 条，单条 300 字；达到上限引导整理。送入模型的上下文另设长度上限，超出时让用户选择，不静默截断约束。所有上限由宿主校验，用户输入作为数据安全编码。

### 保存、恢复与隐私

记录存于应用数据目录，不自动创建或修改用户仓库中的 AGENTS.md、README 或其他文件。项目记录更新有独立 revision，冲突时保留草稿并提示合并。

保存成果时附上当时已确认记录的只读快照，作为成果的配套元数据，不改变源码清单。恢复成果副本默认带回这份记录；待办保留原状态并提示重新核对，最近任务事实重新计算。旧成果没有记录快照时不借用今天的笔记冒充历史，可选择另行复制当前记录并标明来源。

源码导出默认不含项目记录、会话和反馈截图；用户可明确勾选导出项目说明，并在清单中预览。删除笔记不承诺同步删除既有成果记录或已经发送的会话内容。

## 三、阿启：对着预览说清楚修改

### 用户流程

预览工具栏增加“标注修改”。用户截取当前可见预览，或粘贴/上传截图；在静止画面上添加编号框和文字，必要时裁剪或遮盖私人信息。右侧列出“1. 标题往上移；2. 按钮颜色更明显”等要求。发送前显示目标项目、会话和画面来源。

点击发送后，图片、编号说明及上下文进入同一条原生会话消息。只是进入标注或保存草稿不会修改文件。运行中保留反馈草稿并显示忙状态，不承诺排队；用户停止当前任务后可明确重试。提交已被接受但响应丢失时，先对账请求与会话，不能生成新请求盲目重发。

标注草稿按 projectId + sessionId 绑定，收起和切换后仍可找回；不跟随当前选中项目改归属。重启恢复草稿但不发送。页面更新后原截图保持不变，标为“较早画面”，用户可保留或重新截取。

### 截图路径与技术边界

现有项目运行在独立来源的 iframe，父页面不能直接读其 DOM 并绘制截图。首版选择用户主动触发的浏览器截图：`getDisplayMedia` 获取当前标签页，`Region Capture` 裁出预览容器，成功后再读取裁剪帧。每次截图都需要用户操作和浏览器授权，不能后台自动截屏。[MDN 屏幕捕获说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)

先探测能力，并确认捕获的是本标签页。只有裁剪成功后才取帧、编码或上传；选错窗口、拒绝权限、不支持或裁剪失败时立即停止所有媒体轨道，转为粘贴/上传截图。预览区域内暂时隐藏宿主浮层，防止其遮挡内容；裁剪会包含遮住目标区域的像素。该路线是基于官方接口的实现选择，尚未在本产品验证。[Chrome Region Capture](https://developer.chrome.com/docs/web-platform/region-capture)

当前桌面启动器使用系统浏览器。首版不捆绑 Chromium，不承诺所有浏览器均有内置截取能力；不支持时保留完整的图片标注和文字反馈流程。若后续需要免交互自动封面或统一浏览器能力，单独评估宿主截图运行器、包体、更新和运行条件，不以移除预览隔离作为替代。

### 首版支持与限制

- 编号矩形、文字、撤销/重做、删除、裁剪、实色遮盖；不做自由画笔、OCR 或自动 DOM/源码定位。
- 标注使用相对于截图的归一化坐标，缩放窗口不改变指向。键盘可选择标注、编辑说明、删除；不能使用画布时仍可提交编号文字和图片。
- 未遮盖原始画面仅在浏览器内存中处理；持久化和发送的基底必须已经执行用户裁剪/遮盖，不能通过撤销或隐藏图层恢复私人像素。
- 一次反馈先限制一张图、最多 12 个标注。图像大小同时受产品上限和运行时 `imageLimits` 限制；按更严格者执行。降采样前提示，不悄悄改变标注语义。
- 自动记录 previewId、项目、会话、当前文件/成果版本、时间及视口尺寸。跨来源 iframe 内实际导航路径不可直接读取；未知时允许用户填写，并标为用户提供，不用初始 URL 冒充当前路由。
- 用户上传图片标为“用户提供”，可以用于反馈，不能视为宿主验证过的成果封面。
- 历史成果上的反馈保留 versionId。修改当前项目可能已有差异，发送前明确选择“修改当前项目”或“从此成果建立副本”；不写入历史快照。
- 使用当前模型的图片能力。无法确认其支持图片时提示选择支持的模型，或只发送用户确认的文字；不能说“已看到截图”却实际只传了文本。

## 四、作品沿岸：让成果可辨认、可回看

### 用户流程

保存成果成功后，提供可跳过的“拍一张封面”和“放到沿岸”。六个位置仍展示当前项目选定的版本；成果总数不受六个位置限制，全部成果在拾页历史中查看。

每个展品包含真实截图或文件类型图示、标题、版本短标识和保存日期。点开显示完整版本标识、成果说明、对应历史试玩、继续修改和交付入口。点击、键盘和轻量模式共用相同操作。

“更换展品”选择明确成果，“调整位置”交换或移入空位，“移出沿岸”仅取消引用；均不删除成果。首版用菜单和键盘提供完整操作，不依赖拖拽。六个位置保持现有空间，不新增空建筑。

### 封面可信度与失败处理

封面必须来自所选成果快照的实际预览，复用第三项截图能力。刚保存的成果不能直接挪用工作目录的旧画面。图片仅记录被观察到的一刻；远端内容、浏览器本地数据和动态场景不因此成为成果源码的一部分。

当前预览服务会替换同项目已有预览。为历史版本拍封面前明确显示“将切换到此成果预览”；用户取消则保留现有预览。首版沿用一个项目一个预览，不为拍照偷偷启动第二个进程，也不在结束后自动重启被替换的 Node 服务。

封面对象记录 versionId、manifestHash、previewId、时间、视口、图片哈希和捕获方式。截图来自用户授权的浏览器画面，不是独立服务端渲染证明；宿主校验预览归属，用户确认画面。切换预览、导航离开已登记来源或无法可靠确认来源时，不接受为版本封面，使用图示。对任意项目的外部导航识别能力必须在开发探针中验证；无法保证时收紧为可确认的静态历史预览范围，并显示限制。

保存成果与保存封面是独立操作。截图授权拒绝、页面无法运行或图片保存失败，不回滚已保存的文件成果，也不显示虚构封面。重拍只更新展示元数据和 coverRevision，不修改不可变源码快照；上一张封面引用保持到新图发布成功。

历史封面不随当前项目修改自动刷新。首版不接受生成图片、示例截图或任意上传图片充当成果运行截图。没有截图时统一使用真实文件类型图示，无需阻塞展示。

## 共用的数据与接口约定

Harness 继续唯一拥有 Workspace、Session、模型消息、工具和权限。新领域模块只保存产品元数据、媒体及引用，不建立第二套聊天记录或执行器。所有持久化修改仍在 `/creation/projects/` 下，保留旧 `/creation/api`。

以下为拟定结构，开发时可在不改变产品语义的前提下调整：

| 对象 | 关键字段与归属 | 持久化规则 |
| --- | --- | --- |
| StarterDefinition | id、version、双语说明、入口、manifestHash、来源 | 随包只读目录，创建时验证清单 |
| ProjectNotes | projectId、revision、brief、decisions、todos、useAsContext | 原子保存，AI 建议不直接覆盖 |
| ResumeProjection | projectId、sessionId、runId、lastVersionId、来源时间 | 由宿主事实派生；失效时重算 |
| FeedbackDraft | projectId、sessionId、revision、captureId、annotations、text、requestId? | 宿主草稿，发送不确定时对账；不自动提交 |
| Capture | id、projectId、sessionId?、versionId?、previewId?、source、imageHash、尺寸、时间 | 只存已裁剪/遮盖图，不含原始全屏帧 |
| AchievementContext | projectId、versionId、notesRevision、已确认记录副本 | 与成果提交一起发布；旧成果可缺省 |
| Cover | projectId、versionId、captureId、manifestHash、revision | 可替换元数据，源码快照保持不变 |
| Showcase | projectId、revision、六个 versionId 或空位 | 一次原子更新完整位置数组 |

媒体放在应用私有的 `open-projects/media/`，示例试玩放在应用拥有的临时目录。用户源码、模型配置和项目元数据彼此分离。明确 MIME、实际解码、像素数、字节数与项目归属校验；暂定持久化图最大 4,096px 长边、16MP、8MiB，按运行时更严限制收紧。封面生成 640×360 缩略图，等比留边，不裁掉被说明的内容。

元数据状态拟从 version 1 迁移到 version 2：校验原文件、保留本地迁移备份、补充可空字段、原子替换；失败保持原数据可读。新版不得删除旧成果或重算其标识。旧程序不能直接读取新 schema，回退须用明确的备份恢复流程，不能暗中丢弃新版记录。

沿用 `/command` 写入口，增加 starter-copy、notes-save、feedback-save/delete、cover-set/clear、showcase-set 等判别操作；示例清单/详情、媒体读取新增只读接口。具体路径及类型在实现准备任务中收敛。所有写请求使用持久 requestId，相同 ID 与相同参数返回同一结果，不同参数拒绝。示例目录创建与 Workspace 注册需事务日志处理跨存储中断，不能仅在完成后写 receipt。

笔记、反馈和展示分别检查对应 revision，避免编辑笔记与换展品互相覆盖；已有成果保存 revision 约束继续保留。上传先写临时对象，通过校验后发布引用；失败不出现半张图。只清理应用拥有、无引用且超过保留期的对象，首版保留期为 7 天，不删除运行时管理的会话附件。

世界桥从协议 2 升为 3 时同步 React、加载壳和 Godot。世界仍只接收展示状态并发送意图，不获得宿主文件路径、模型凭据或执行权。传输使用受限的宿主缩略图读取与有界二进制/编码数据方案，由开发探针确定；不接受用户项目提供的任意图片 URL，不给预览页面复用世界桥。

## 开发顺序与可拆分交付

1. 做四个局部能力探针：上下文作用域、图片消息提交、浏览器区域捕获、世界缩略图传输；同时确定状态迁移与持久请求事务边界。探针结果写入开发记录，不以接口声明代替实际连接结果。
2. 完成共用元数据与兼容迁移，然后实现灵感夹四个示例、复制流程、项目记录及继续提示。这一批不依赖截图，可以独立形成有价值的增量。
3. 完成截图与媒体服务、反馈草稿、标注编辑器及原生消息提交。图像能力被浏览器阻塞时保留上传反馈路线，继续推进其他模块。
4. 接入版本封面、沿岸更换和排序、轻量模式等价呈现；收敛四项的连续体验。
5. 主体功能连通后另行集中验收、修复、打包。当前用户要求先规划，**本轮不启动此步骤**。

不预估未经验证的工期。每批保存清晰版本，实际提交和推送按当时用户授权执行。已有 0.2.0 验收不能替代上述新能力验证。
