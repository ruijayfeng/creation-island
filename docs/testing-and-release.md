# 统一测试与交付

> 2026-10-08：下文具体场景属于已有三类作品版本；测试时机和如实记录原则继续适用。开放式创作的完成判据已改为 [产品终态](product-spec.md) 中的项目创建、真实执行、岛内交互、预览、成果与交付闭环。后续需据此重写集中测试场景，本轮不执行测试，也不把旧结果当作新方向通过。

## 测试时机

按用户要求，先完成整体开发，再统一测试并修复 bug。开发阶段只做必要的编译、启动和当前连接点检查，完整功能、异常、真实模型和发行包测试在主体开发结束后集中开展。

不为每一步编写大量测试，不为可逆样式或文案修改补形式化测试，不反复执行全套回归。明显阻塞开发的问题及时修复，其他问题进入问题表。已有测试保留，在统一测试阶段按改造范围运行；对版本覆盖和取消竞争等高风险逻辑补少量针对性检查。

运行时的数据校验、错误处理和取消保护是产品功能，开发时就要实现；它们与批量执行测试不同。

## 进入统一测试的条件

三种作品、创作室、作品管理、小岛展示、模型配置和两类导出全部接通，最终视觉素材到位，能够生成候选桌面包。此时功能状态为已实现待验收。

## 集中执行顺序

1. 构建候选包，记录版本、依赖锁文件和环境；执行与实际改造相关的已有检查。
2. 在干净数据目录走完三种作品的主流程，集中检查窗口缩放、长文、键盘、空状态和动效。
3. 集中检查取消、失败、恢复、重启、并行编辑、文件边界和资源加载。
4. 使用真实模型检查生成与指定修改，记录输出、耗时、修复和失败。
5. 在无开发环境的支持平台检查候选包；在另一台电脑、断网且没有宿主服务时打开导出作品。
6. 汇总问题，集中修复阻断与高影响问题。修复后回归对应场景和受影响的相邻路径。
7. 对最终发行包再做一次主流程冒烟及必要的异常复验，记录最终文件摘要。

## 最终完成标准

完成以实际行为为准。三种作品都必须走通主流程，异常能力不能只在一种模板下有效。

| 验收场景 | 必须发生的结果 |
| --- | --- |
| 首次安装启动 | 无开发工具可启动，有样例和创作入口 |
| 不配模型试玩 | 三种样例都能完整体验，不发起模型调用 |
| 配置模型 | 成功可生成；错误可解释且不丢草稿 |
| 创建三种作品 | 从自然语言到可玩的候选，用户采用后可继续编辑 |
| 直接编辑内容 | 即时预览正确，草稿保存状态准确 |
| 修改指定内容 | 修改目标正确，未授权的内容不被覆盖 |
| 修改主题 | 内容和交互规则保留，预览与导出样式一致 |
| 拒绝候选 | 当前草稿和保存版本保持可用 |
| 模型输出非法内容 | 拒绝或最多修复一次，说明原因，不能执行返回的代码 |
| 超范围需求 | 明确说明限制，用户决定是否接受替代范围 |
| 取消和迟到响应 | 已取消结果不得写入作品 |
| 重复提交与并行编辑 | 不重复发起模型请求，不用过期结果覆盖新内容 |
| 生成中关闭再打开 | 旧内容可读，任务标为中断，不自动重复执行 |
| 保存失败 | 不假报成功，旧版本存在，用户可重试 |
| 保存与恢复版本 | 恢复后的内容和互动可重现，历史仍可查看 |
| 删除与还原 | 回收站可还原，任务及展示位同步处理 |
| 展示作品 | 六个槽位正确引用保存版本；替换不删除收藏 |
| 导出可玩文件 | 断网、无宿主服务的另一台电脑能完整使用 |
| 导入可编辑作品包 | 新建独立作品、可继续编辑，不覆盖同名项 |
| 文件与凭据边界 | 生成不调用任意文件工具，导出包不含密钥和本机路径 |
| 世界加载失败 | 能直接打开收藏及创作室，作品不受影响 |
| 最终发行包 | 启动、退出、重启和数据目录正确，无个人开发状态 |

对于模型生成的语义质量，还需用固定输入覆盖三种类型的明确需求、模糊需求和局部修改，各运行多次并人工试玩。记录实际失败，不能用单元测试或一次演示代替模型验证。所有对外宣称的能力都必须有对应验收。

## 有限规模的真实模型检查

每类作品选三个场景：完整需求生成、缺失信息后生成、对已保存作品做指定局部修改。每场景独立运行两次，共 18 个场景运行；澄清和修复可能含额外调用，记录实际请求次数与费用。每次最多自动修复一次。

只有发现结果波动、同类失败集中或修复影响扩大时，才补相应场景。无需默认跑多模型排行榜或大量随机任务。人工复核内容并实际试玩，自动化承担结构、引用、范围和状态等可确定规则。此规模用于交付检查，不作为线上成功率宣传。

## 问题分级与记录

| 级别 | 例子 | 交付处理 |
| --- | --- | --- |
| 阻断 | 无法启动、密钥进入导出、误覆盖作品、文件不能独立运行 | 修复并复验后才能交付 |
| 高影响 | 一种作品无法完成、恢复错误、取消后覆盖内容 | 修复并复验后才能交付 |
| 一般 | 有绕行方法的界面问题、不影响内容的视觉瑕疵 | 按影响修复，保留项明确记录 |

问题表字段为编号、版本、复现步骤、预期、实际、级别、关联作品或任务、修复说明、回归结果。验收记录包括场景、实际环境、结果、关联问题和证据位置。

初始不填通过。原 QCode 的测试结果、截图和发行包不能代替新产品验收。如果缺少另一台电脑等验证条件，保留未验证状态，不代填通过。

## 最终交付物

可运行应用包、文件摘要、使用说明、支持范围、三类内置样例及导出文件、实际验收记录、已知限制和随包的第三方声明。发行包不含开发密钥、个人配置、用户作品或本地状态。
