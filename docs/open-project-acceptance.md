# 开放项目 0.2.0 本机验收

2026-10-08。该记录只针对开放项目实现，不引用旧三类作品验收代替新主流程。环境：Apple Silicon macOS 26.5.1、Node 26.8.1、Godot 4.7.2、Chrome 154。真实模型为已配置的 DeepSeek-V4-Flash High。隔离数据目录位于本仓库忽略的 `tmp/open-project-acceptance-home`；没有改变用户原应用数据。

## 集中修复

- API 前缀尾斜杠导致注册不匹配：统一使用宿主的前缀注册语义。
- 原生会话失败被显示为结束：从真实 turn/end 原因区分失败/中断。
- 预览不同端口仍共享主机 Cookie：改用不同本地主机名，限制项目 API 的宿主来源。
- 预览旁对话溢出面板、切项目读取响应过期：加入裁剪边界及失效响应保护。
- 新建想法跨项目串显示：独立保存每项目待发送想法，保留原生会话草稿。
- 停止轮次未停止后台 Bash：使用固定运行时公开 jobs 接口，只停止同会话拥有作业，等待真实资源释放后再保存差异/释放锁；不修改 Harness/vendor。
- 旧命令去重记录在重启后返回旧 ready URL：重复启动请求查询当前拥有的预览，无进程时返回 stopped。
- 历史成果文字在世界中受遮挡：调整标牌绘制顺序、字号与描边。

## 可重复检查

先 `corepack yarn build:web`，再运行：

```sh
node --test scripts/test-open-project-files.mjs
node scripts/test-creation.mjs
corepack yarn check:vendored-runtime
corepack yarn check:doc-i18n
```

文件/预览检查共四项；Node 进程测试实际启动和停止服务。`scripts/verify-open-project-api.mjs` 需要运行中的隔离应用，通过 `DSH_HOME` 指定其数据目录，会新建验收项目并检查真实保存/恢复/构建/导出。不要指向日常用户数据。

`scripts/verify-open-project-cancel.mjs` 是会调用真实模型的浏览器取消回归；显式提供 `PLAYWRIGHT_MODULE`、`CREATION_TEST_HOME`、`CREATION_TEST_PROJECT_NAME`、`CREATION_TEST_PROJECT_PATH`，均须指向隔离验收环境。脚本停止后台延迟写入后继续等待，检查不存在迟到文件。

## 仍有限制

- 本机有限场景验收；另一台无开发环境的 Mac、跨设备离线导出试玩和 Apple 开发者签名/公证未完成。
- 仅提供静态目录及明确 Node 脚本；未知栈、框架依赖、额外系统工具或云服务需要实际环境。Node 预览及明确确认的构建使用本机权限，不宣称具备模型工具沙箱。
- 浏览器预览端口重新分配时，其 localStorage 属于不同来源；需要长期保存的数据应写入项目或由项目提供导入导出，不能依赖临时预览来源。
- 快照保守排除已知凭据、Git、缓存和全部符号链接；不能自动辨认所有私密内容。用户应检查交付清单；源码包不含 Git 历史。
- 没有公网部署、跨项目队列、多设备同步或任意技术栈成功保证。静态构建只验证构建和 HTTP 可访问，功能仍需逐项操作。
- 外部进程修改文件时通过双次清单校验拒绝不一致；无法阻止应用外程序继续修改当前项目。快照始终只引用已保存的不可变对象。

最终桌面 ZIP、源码提交、独立解压验证和摘要在本记录交付段补充；未完成前不宣称最终包已验收。
