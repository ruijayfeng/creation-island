# 开放式创作方向纠正说明

2026 年 10 月 8 日。用户明确要求回到开放式 AI 项目创作，并暂停开发，先厘清最终产品。新目标以 [产品终态](product-spec.md) 和 [产品体验](product-experience.md) 为准。本文记录改造边界，防止下一轮继续沿三类模板工作台扩展。

## 已确定的方向

小岛为主界面；真实项目为工作对象；阿启为主要制作伙伴。拾页负责项目和历史，阿渡负责文件及交付。角色化入口调用同一项目能力，不各自维护一套模型任务。默认流程在岛内完成，专注模式和高级工作台按需进入。

问答、贺卡、分支故事从能力边界降为可选示例。第一轮重点保证网页、小工具和轻量 Web 游戏从需求到运行的体验，不宣传任意语言、环境或部署目标都已经支持。

## 现有成果如何处理

| 已有内容 | 新方向中的处理 |
| --- | --- |
| 公开 MIT 地图、角色、场景交互 | 保留空间与交互基础，按品牌方案改造角色、道具和标牌；世界状态与真实项目工作对应 |
| Workspace、Session、原生对话、模型和工具能力 | 作为开放项目工作的基础；接通岛内入口时逐项核对，不能假定旧代码原样启用即可通过验收 |
| 本地启动器、Apple Silicon 打包、独立数据目录 | 继续复用，不为交互纠正同时更换运行载体 |
| 暖白与深绿、字号、焦点、窄屏经验 | 保留，用于岛内面板，不保留覆盖地图的门户式首页 |
| 三类作品的内容 schema 与无工具生成服务 | 不作为通用创作执行引擎，不扩成任意项目协议 |
| 固定字段的候选差异与采用逻辑 | 仅属于原三类作品；开放项目改为真实文件变化、运行检查和成果确认 |
| 版本恢复和实际差异的产品经验 | 保留原则；项目文件快照和恢复副本需要新设计，不能复用一份 JSON 就宣称完成 |
| 三类作品编辑器与导出 | 保留兼容访问，可作为旧版作品工具；不再是默认主路径 |
| 最近作品网格、独立三栏工作台 | 不作为新的默认首页与主交互，能复用的组件按岛内场景重新组织 |

本轮不删除、清空或迁移用户已有数据。后续保留“旧版互动作品”兼容入口及既有导出能力。旧 isle.json 仍是旧作品协议，不伪装成任意项目包；需要转为项目时由用户明确选择并生成新副本，保留原作。

## 与原版的关系

原版的可取部分是角色承接真实项目操作、岛内对话、后台执行和会话恢复。恢复这些是方向纠正的起点。

本产品进一步要把“能发任务”做成“能够持续完成作品”：预览有实际运行依据，本轮结束和用户确认分开，成果节点引用明确版本，展品能回到真实项目，交付说明与文件一致。这些是新增目标，不宣称原版已经全部具备。

## 在开发前还需核对的条件

以下是实现目标时的必要技术决策，不改变用户侧应有的行为，也不代表当前实现具备这些能力。

| 条件 | 产品必须保持的行为 | 待核对内容 |
| --- | --- | --- |
| Agent 权限 | 真实展示权限和待授权动作；拒绝不绕过 | 固定运行时的权限预设、项目外访问、命令审批能力，不能用角色提示词充当隔离 |
| 项目预览 | 预览属于当前项目/成果版本，有可观察的可用和失败状态 | 运行命令、进程归属、端口、生命周期、隔离的嵌入或外部窗口；不信任模型自报成功 |
| 成果保存 | 记录明确文件状态，保存失败不假成功 | 对源码、资源、未跟踪文件、大文件和排除项的快照规则；不包含依赖缓存或凭据的公开导出 |
| 恢复 | 原项目和 Git 历史不被静默覆盖 | 默认建立恢复副本；外部改动和正在运行的任务如何处理 |
| 交付 | 文件清单和运行说明与实际结果一致 | 构建产物检测、配置示例、凭据与私人文件排除、清洁环境验证 |
| 后台与切换 | 关闭不取消，重连不重发，项目之间不串记录 | 原生 Session 恢复、通知去重、全局写入任务约束和排队是否可靠 |

其中预览、文件快照、任务和权限分别由真实服务核验，不依靠模型生成一句“已完成”确认。实现能力不足时应明确限制操作，而不是做一个看似成功的按钮。

## 后续设计要证明的画面

下一轮视觉与交互应围绕六个真实状态组织：首次进入岛屿、阿启接收新想法、任务在后台执行、等待用户授权、实际结果与修改、保存成果后回到展示区。每张画面都应显示当前项目、主要操作和返回关系。

这些画面是后续设计交付内容，本轮只有文字规格与流程关系，没有已实现原型或新版界面。代码开发、模型调用、打包和测试均不在本轮执行。
